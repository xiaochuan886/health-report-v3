# 综合健康检测报告第二阶段渲染设计

## 目标

在第一阶段已经产出的结构化中间结果基础上，完成第二阶段的报告组装与 PDF 输出链路：

- 消费 `matched_indicators.json`、`summary_sections.json`、`nutrition_sections.json`
- 生成一份适合 `md2pdf` 渲染的 Markdown 报告
- 使用 `md2pdf` 输出首版 PDF

第二阶段不重新参与指标匹配、参考值解析、风险判定，也不改动第一阶段的数据规则。

## 范围

本阶段只覆盖以下内容：

- Markdown 报告模板设计与数据组装
- 三大主板块内容渲染
- 首版 PDF 生成链路
- 文档风格下的简化风险表现

本阶段明确不做以下内容：

- 复刻 Power BI 趋势图
- 复杂图表组件
- 重新设计检测规则或白名单规则
- 修改标准库 Excel 内容
- 处理历史趋势对比

## 设计原则

### 1. 结构沿用，视觉简化

首版报告保留现有报告的章节结构和阅读路径，但不强行复刻 Power BI 的图形布局。视觉上改为更适合 `md2pdf` 的专业文档风。

### 2. 数据层与渲染层彻底分离

第二阶段只读取第一阶段产出的中间 JSON，不再直接读取客户 `xls` 或标准库 `xlsx`。这样可以避免模板调试反复影响规则层。

### 3. 优先输出稳定文档

优先选择 Markdown + 表格 + 状态标签 + 简化风险刻度条的表达方式，保证首版 PDF 稳定可交付。

## 首版报告结构

Markdown 首版报告固定为以下 8 个部分：

1. 封面
2. 基础信息
3. 目录
4. 第一部分 评估结果小结
5. 第二部分 癌症健康监测与指导
6. 第三部分 心脑血管健康监测与指导
7. 第四部分 大营养检测与建议
8. 第五部分 医学名词释义与健康生活指南

## 各部分内容边界

### 1. 封面

封面展示固定信息：

- 报告标题
- 客户姓名
- 报告日期
- 检测机构名称

封面优先使用文档风排版，不加入复杂背景设计。

### 2. 基础信息

基础信息单独成页，放在封面之后、目录之前。该页用于承接客户信息和检测信息，避免与结果小结混排。

首版基础信息页展示：

- 姓名
- 性别
- 年龄
- 样本信息
- 接收时间
- 报告时间
- 送检机构

若某些字段暂时未抽出，则允许留空，不阻塞报告生成。

### 3. 目录

目录由 Markdown 标题生成，对应正式章节结构，不单独维护静态文本目录。

### 4. 第一部分 评估结果小结

结果小结只保留两块：

- 癌症健康监测小结
- 心脑血管健康监测小结

大营养检测不进入第一页摘要。

#### 癌症健康监测小结

- 按疾病类型分组展示
- 每组只展示异常或接近临界的指标
- 同一疾病组下列出指标名称、结果、参考值、状态

#### 心脑血管健康监测小结

- 不按疾病再拆分
- 将相关异常或接近临界指标整合展示
- 展示指标名称、结果、参考值、状态

### 5. 第二部分 癌症健康监测与指导

按疾病类型分组展开。

每组首版展示以下内容：

- 疾病类型名称
- 命中指标结果表
- 指标类型标签：特异性 / 辅助判断
- 简短结果说明

本阶段不生成复杂疾病风险评分，只做基于命中指标的结果呈现。

### 6. 第三部分 心脑血管健康监测与指导

按统一结果表展示，不再拆疾病类型。

首版展示：

- 指标名称
- 本次结果
- 参考值
- 状态
- 简短说明

### 7. 第四部分 大营养检测与建议

该部分分为两个子部分：

#### 4-1 评估结果检测

再拆成两个结果区：

- 微量元素检测结果
- 维生素检测结果

每区只展示“本次命中的白名单指标”，并展示：

- 指标名称
- 本次结果
- 参考值
- 状态
- 简化风险刻度条

#### 4-2 结果解读与建议

只展示本次命中的白名单指标，不展示未命中项。

按指标输出说明内容，字段来源为 `指标说明`，展示为：

- 项目
- 临床表现 / 具体意义
- 饮食补充 / 临床应用

说明与建议与结果表分开展示，不做“单项结果内联建议”的布局。

### 8. 第五部分 医学名词释义与健康生活指南

V1 同时保留两部分，但都做精简版：

- 医学名词释义：只收录本次命中的关键癌筛 / 心筛指标
- 健康生活指南：保留固定精简内容，不做个性化生成

## 风险表现设计

首版不做趋势图，只保留简化风险刻度条。

风险状态来自第一阶段，不在第二阶段重新计算。页面只消费以下状态：

- `above`
- `below`
- `near_upper`
- `near_lower`
- `normal`
- 多段规则状态，如 `不足`
- 无法判断时使用 `unknown`

Markdown 表达方式遵循“稳定优先”原则：

- 用文本标签表达状态
- 用简单字符条或短文本表达风险刻度
- 不依赖复杂嵌入图表

## 数据输入与接口约定

第二阶段输入固定为第一阶段导出的 3 个文件：

- `matched_indicators.json`
- `summary_sections.json`
- `nutrition_sections.json`

建议新增一个渲染输入装配层，负责：

- 读取 JSON
- 抽取基础信息
- 组织各章节视图模型
- 输出 Markdown 所需上下文

Markdown 模板层只做渲染，不承担规则判断。

## 建议文件边界

建议第二阶段实现时按以下职责拆分：

- `src/report_pipeline/render_inputs.py`
  - 读取中间 JSON
  - 组织页面级上下文

- `src/report_pipeline/markdown_report.py`
  - 负责 Markdown 字符串拼装

- `src/report_pipeline/report_styles.py`
  - 负责状态标签、风险刻度条、通用格式化小工具

- `src/report_pipeline/cli.py`
  - 增加第二阶段命令入口

若后续接 `md2pdf`，再新增：

- `src/report_pipeline/pdf_export.py`
  - 调用 Markdown 转 PDF 的脚本或封装

## 输出产物

第二阶段的最小交付产物为：

- 一份 Markdown 报告
- 一份 PDF 报告

建议默认输出到：

- `output/report.md`
- `output/report.pdf`

如按客户单次执行，可落在客户输出目录中，例如：

- `output/customer-run/report.md`
- `output/customer-run/report.pdf`

## 错误处理原则

第二阶段渲染不因单个字段缺失而整体失败。

约定如下：

- 单字段缺失：显示为空或 `--`
- 某板块无数据：保留标题并显示“本次未命中相关指标”
- 说明项缺失：保留结果，不阻塞整个报告

PDF 生成失败时，应至少保留 Markdown 产物。

## 测试策略

第二阶段测试分为三层：

### 1. 组装层测试

验证 JSON 输入可以被转换为稳定的页面上下文。

### 2. Markdown 渲染测试

验证章节标题、摘要块、营养板块、释义块都能按预期输出。

### 3. 端到端测试

使用当前真实客户中间结果，生成 Markdown，并在可用环境下尝试生成 PDF。

## 已确认决策

- 采用“结构沿用、视觉简化”路线
- 基础信息单独成页
- 医学名词释义与健康生活指南都保留，但先做精简版
- 第一部分小结只保留癌筛和心筛
- 大营养检测拆成“结果”和“解读与建议”两层
- 第二阶段只消费中间 JSON，不回读原始规则数据源

这不影响继续编写实现计划和执行代码，但需要明确记录。
